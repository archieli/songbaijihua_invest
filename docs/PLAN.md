# 松柏计划投资管理系统 — 产品与实施方案

## 一、Context

松柏计划（兰启昌，2025-09-06 启动课）是一个面向大陆投资者的长期资产配置方案：
中国股票 25% / 美国股票 25% / 中国债券 30%（30 年国债 15% + 主动债基 15%）/ 黄金 20%，
场内 ETF 一次性买入，每年再平衡一次，不择时、长期持有。

课程本身讲清了"为什么"和"买什么"，但学员在"执行"环节反复卡在几个共同的问题上：
算不清、记不住、不敢买、每月有钱不知道怎么投。本项目做一个**纯前端静态网页工具**，
把这些执行环节全部自动化，用户只做"审核 + 下单"。

已确认的架构决策：
- 纯前端静态站（Vite + React + TypeScript），数据存浏览器本地，支持 JSON 导出/导入；部署到 GitHub Pages / Vercel。
- 行情由脚本抓取后打包成静态 JSON，GitHub Actions 定期更新。
- "抄作业"第一版做成管理员维护的**示范账本**（只有日期与操作类型，不含金额），无需登录。

项目目录当前为空（只有空的 CLAUDE.md），从零搭建。

## 二、用户痛点归纳与解决方案

把群里零散的反馈归为 5 类共同困惑，每类对应一个工具模块：

| # | 共同困惑 | 课程给的原则 | 工具解决方案 |
|---|---|---|---|
| 1 | **再平衡时间记不住；中途加仓后"一年"从哪天算** | 每隔一年再平衡一次 | 周年日锚定**首笔买入日**，中途加仓不改锚点；再平衡完成后下一次 = 本次再平衡日 + 1 年。到期前 7 天、当天、逾期分级提醒；可导出 .ics 日历事件（年度循环）。 |
| 2 | **再平衡比例算不清、怕算错** | 卖超配、买低配，回到目标比例 | 系统按当前市值自动生成**交易单**（每只基金卖/买多少份，按 100 份整手取整，估算佣金，显示调整前后占比），用户只审核并勾选"已执行"，系统自动记账。 |
| 3 | **不知道自己能投多少、下一年能投多少** | 单次买入 ≤ 家庭净资产 5%（保守）/10%（稳健）；首笔 10-100 万；做好 -20% 心理准备 | **仓位规划器**：输入家庭净资产、紧急备用金、3 年内用款、负债、月收入/月支出，输出：单次买入上限、本年度可投额、分批方案（<20 万一笔；50-100 万分 12 月；>100 万分 2-3 年）、压力测试表（-15%/-20%/-30% 对应的账面亏损额，作为自我测试）。 |
| 4 | **每月有固定结余想定投，但场内 + 年度再平衡怎么兼顾** | 课程未展开 | **现金流再平衡**：每月新增资金不按 25/25/15/15/20 平均买，而是**全部买入当前最低配的资产**（按缺口比例分配，只买不卖）。这与年度再平衡不冲突，反而减少年度调仓量。工具每月生成一张"本月买入单"（考虑 100 份整手，小额资金只买 1-2 只，余额结转下月）。年度锚点仍按首笔买入日。 |
| 5 | **不敢入场，总想等低点；想抄作业** | 不必择时，长期持有才是关键；种树最好的时间是十年前，其次是现在 | **历史模拟器**：任选起点日期、金额、一次性或分批，看"如果那时投了，今天值多少"，并对比"再等 3/6/12 个月入场"的结果；附"过去 N 年任意一天入场持有 1/3/5 年"的收益分布。**示范账本**：导师的买入/加仓/再平衡时间线，可一键"按此节奏生成我的计划"。 |

## 三、功能模块（页面）

1. **仪表盘** — 当前市值、各资产实际占比 vs 目标（偏离条）、累计收益、下次再平衡倒计时与提醒横幅、行情数据日期。
2. **记账** — 记录每笔买入/卖出（日期、基金、份数、成交价、手续费），支持多笔加仓；从交易单一键入账。
3. **再平衡** — 自动生成交易单 → 审核 → 确认入账。展示课程 P29 同款"再平衡表"。
4. **每月定投（现金流再平衡）** — 输入本月可投金额，生成买入单。
5. **仓位规划器** — 家庭财务输入 → 可投额、分批方案、压力测试。
6. **历史模拟器** — 任选起点/金额/方式/是否年度再平衡 → 曲线、市值、年化、最大回撤、延迟入场对比。
7. **示范账本** — 时间线展示 + 按节奏生成计划。
8. **设置** — 佣金费率、风险类型、目标比例（默认锁定为松柏计划，可显示但需显式解锁修改）、数据导出/导入/清空。

移动端优先（群成员多用手机），中文界面，颜色/术语与课件一致（蓝色主色）。

## 四、技术方案

### 4.1 技术栈
- Vite + React 18 + TypeScript，React Router（hash 路由，兼容 GitHub Pages）。
- 状态：zustand + `persist` 中间件（localStorage）。
- 图表：Recharts。日期：dayjs。
- 样式：Tailwind CSS。
- 测试：vitest（领域纯函数）。
- 部署：GitHub Pages（Actions 构建）或 Vercel；Actions 每周 cron 跑抓取脚本并提交行情 JSON。

### 4.4 核心算法

**锚点与提醒（schedule.ts）**
- `anchorDate = 首笔买入日`；`nextRebalance = (lastRebalanceDate ?? anchorDate) + 1 年`；加仓/定投不改变锚点。
- 提醒等级：`>7天` 无 / `≤7天` 提前提示 / `当天` 到期 / `<0` 逾期 N 天。
- 提醒落地：页面横幅 + 导出 .ics（RRULE:FREQ=YEARLY）+ 打开页面时可选 Notification API。静态站无法主动推送，需在 UI 明示。

**年度再平衡（rebalance.ts）**
- 输入：持仓份数、最新价、目标比例、可选新增现金、整手 100 份、佣金费率（默认万 3，可设）。
- `total = Σ份数×价 + 现金`；`target_i = total×w_i`；`delta_i = target_i − 当前市值_i`；份数 = `round(delta_i / 价_i / 100) × 100`；先卖后买；余额留作现金。
- 输出：交易单（方向、份数、预计金额、佣金）、调整前后占比表；用课程 P29 案例（20 万 → 21.4 万，调整 -4,500/-8,500/+1,100/-3,100/+15,000）作为单测基准。

**现金流再平衡（cashflow.ts）**
- `total' = total + M`；`gap_i = max(0, w_i×total' − 当前市值_i)`；若 `Σgap ≥ M` 按 gap 比例分配 M，否则先补满缺口，余额按目标比例分配；再按整手取整，不足一手的余额结转下月并记录。

**仓位规划（sizing.ts）**
- 长期可投资金 = 净资产 − 紧急备用金 − 3 年内用款；单次买入上限 = 净资产 × 5%/10%（按风险类型）。
- 分批规则按课程：<20 万一笔；20-50 万可选；50-100 万分 12 月；>100 万分 2-3 年。
- 月度定投建议 = 月结余 × 比例（默认 50%，标注为工具默认值而非课程规则，可改）。
- 压力测试：投入额 × (-15% / -20% / -30%) 的金额与占净资产比。

**历史模拟（backtest.ts）**
- 使用前复权收盘价（含分红）。参数：起点、金额、方式（一次性 / 按月分 N 份 / 按年分 N 份）、是否周年再平衡。
- 输出：市值曲线、累计收益、年化、最大回撤、各资产贡献；"延迟入场对比"（再等 3/6/12 个月）；"任意一天入场持有 1/3/5 年"的收益分布（中位数 / 最差 / 最好 / 正收益概率）。
- 数据起点限制：159201 成立于 2025-02，511090 成立于 2023-05。默认模拟最早起点 = 各基金最早共同可用日；提供"使用指数回溯"开关，成立前用代理指数（自由现金流 980092、30 年国债指数），界面明确标注"代理数据"。代理指数能否抓到需在实施时验证，抓不到则该资产段禁用回溯并提示。

### 4.5 行情抓取（scripts/fetch-nav.mjs）
- 首选东方财富 K 线接口 `push2his.eastmoney.com/api/qt/stock/kline/get`（secid 形如 `1.518880` / `0.159201`，klt=101 日线，fqt=1 前复权）。
- 备选：天天基金 `api.fund.eastmoney.com/f10/lsjz`（需 Referer）；再备选 Python akshare。
- **本次会话沙箱无网络，接口可用性未验证**，实施第一步即验证并锁定字段。
- 输出 `public/data/nav/{code}.json`；UI 显示"行情更新于 YYYY-MM-DD"，并允许用户手动覆盖某只基金的当前价（数据滞后时的兜底）。
- Actions `update-nav.yml` 每周一 cron 执行并 commit。

### 4.6 数据与隐私
- 所有个人数据仅存于浏览器 localStorage；设置页提供导出/导入 JSON、清空。
- 示范账本 JSON 结构：`[{date, type:'buy'|'add'|'rebalance'|'note', author, note}]`，无金额。

## 五、实施顺序

1. 脚手架：Vite + React + TS + Tailwind + Router + zustand + vitest；`config/plan.ts`；CLAUDE.md 写入项目约定与命令。
2. 验证行情接口，写 `fetch-nav.mjs`，生成 5 只基金 JSON；`data/nav.ts` 加载。
3. `domain/` 六个纯函数模块 + 单测（含课程 P29 基准案例）。
4. 页面：记账 → 仪表盘 → 再平衡 → 每月定投 → 仓位规划 → 模拟器 → 示范账本 → 设置。
5. 移动端适配、导出 .ics、导入/导出 JSON。
6. GitHub Actions：deploy.yml + update-nav.yml；部署并验证线上地址。

## 六、验证

- `npm test`：domain 单测全部通过，再平衡用课程 P29 数字对账。
- `npm run fetch-nav`：5 个 JSON 生成，最新日期为最近交易日。
- `npm run dev` 手工走通：录入首笔（模拟 2025-09-08 买入 20 万）→ 仪表盘显示占比与倒计时 → 中途加仓不改倒计时 → 再平衡页生成交易单并入账 → 每月定投生成买入单 → 模拟器选 1 年前一次性 20 万看结果 → 导出/导入 JSON 后数据一致。
- `npm run build` 后本地预览；推送后 GitHub Pages 线上打开，手机浏览器检查布局。
